# Автоматическое обновление результатов клуба

GitHub Actions → **Update club results** (`weekly-compreg.yml`).

- Плановый запуск: среда, 10:00 МСК (`0 7 * * 3` UTC). GitHub может задерживать старт; это не гарантированное время завершения.
- Ручной запуск: **Run workflow** на ветке **main**. Поле `tournament_url` пустое — проверить результаты за 28 дней. Ссылка Compreg `listcat.php` — проверить конкретный турнир независимо от даты и города.
- Клубный список: `data/club_triumph_spb_dancers.csv`. IDD — основной идентификатор. Если IDD не опубликован в протоколе, используется только однозначная ранее подтверждённая связь в базе: полное имя + клуб + город → IDD. Одинокое совпадение имени не импортируется; оно попадает в сводку для проверки. Противоречащий опубликованный IDD не заменяется совпадением имени.
- Турниры определяются по `https://compreg.ru/results.php`, протоколы скачиваются заново при каждой проверке окна. Изменившиеся релевантные протоколы полностью заменяются транзакционно. Уже разобранный идентичный протокол не импортируется повторно.
- Сайт публикуется после успешного разбора и сборки всех готовых отчётов. Ошибка сети/изменение структуры сайта/потеря исторических протоколов останавливает обновление. Успешное сохранение базы с неуспешной публикацией оставляет маркер повторной публикации.

## Постоянная база

Полная SQLite-база и исходные HTML хранятся в **закрытом** репозитории `Julia-briukva/Dance-analytics-data`, ветка main, каталог state. Это постоянное хранилище с историей Git, а не временный Actions cache. Каждый снимок проверяется `PRAGMA quick_check`, контрольной суммой SHA-256 и числами записей. Восстановление пустой базы вместо полной запрещено. Карточки танцоров с присвоенными классами также переносятся из локального кэша.

Сжатый снимок ограничен 95 MiB на файл; при достижении лимита обновление остановится и потребуется перенести хранение базы в другое долговременное хранилище. Историю private-репозитория нельзя удалять при обычной очистке workflow artifacts. Доступ к Actions приватного репозитория не требуется: код выполняется в основном репозитории, закрытый используется только для состояния.

Конфигурация основного репозитория:

- Repository variable `DANCE_STATE_REPOSITORY` — `Julia-briukva/Dance-analytics-data`.
- Actions secret `DANCE_STATE_SSH_KEY` — приватный SSH deploy key.
- Соответствующий публичный deploy key закрытого репозитория имеет право записи. Он не даёт доступа к другим репозиториям, не является пользовательским PAT и не зависит от срока действия установочного токена.
- Публичные отчёты обновляются встроенным `GITHUB_TOKEN`. Такой push не запускает второй workflow, поэтому новый workflow сам выполняет публикацию GitHub Pages.
- Общая блокировка `pages`, без отмены выполняющейся операции, защищает от одновременных публикаций.

## Однократная установка

Запускается на Mac с полной текущей базой: `python3 ~/Downloads/dance-weekly-auto/install.py`.

Нужен отдельный **временный** fine-grained PAT с владельцем Julia-briukva и Repository access → All repositories, чтобы настройщик мог создать закрытый репозиторий и сразу получить к нему доступ. Repository permissions: **Administration, Contents, Workflows, Actions, Secrets, Variables → Read and write**. Срок 7 дней достаточен. Токен вводится скрыто только в локальный терминал; не передавайте его в переписку. Установщик не записывает его в файлы, remote URLs, git config или Actions Secrets. После установки токен можно удалить.

Установщик проверяет, что локальная main не содержит неопубликованных коммитов; создаёт резервную копию локальной базы; создаёт или использует закрытый репозиторий; переносит полную базу и имеющиеся исходные страницы; генерирует SSH deploy key; сохраняет конфигурацию Actions; атомарно добавляет код автоматизации в текущую main, сохраняя остальные файлы; обновляет локальный checkout и запускает первую серверную проверку. Повторная установка использует существующую облачную базу и не заменяет её устаревшей локальной копией.

Первую установку нельзя считать завершённой до успешного серверного запуска. Следите за вкладкой Actions. Если Pages environment запрашивает подтверждение deployment, подтвердите его в GitHub. В репозиториях с обязательным PR/защитой main прямое обновление остановится — потребуется адаптировать публикацию под эти правила.

## Проверка результата и устранение ошибок

В Summary каждого запуска: список турниров, числа проверенных/обновлённых протоколов, найденные IDD, совпадения для ручной проверки, ошибка при наличии. JSON-сводка сохраняется как artifact `compreg-run-summary` на 30 дней. Исходная база и протоколы от этого срока не зависят.

Если результаты задержались — запустите workflow вручную без ссылки. Для турнира старше четырёх недель — вставьте его ссылку. Ошибку аутентификации хранилища исправляют заменой deploy key и Actions secret, а не повторной сборкой отчётов. При изменениях структуры Compreg сначала исправьте парсер и тесты, затем повторите ручной запуск. GitHub может отключать расписания в публичных репозиториях после длительного отсутствия активности; проверить/включить workflow можно на вкладке Actions.

Локальная база после перехода не обновляется автоматически. Актуальный источник истории — private-репозиторий. Не загружайте старую локальную базу поверх него. Для работы локально восстановите свежий снимок командой `python3 scripts/weekly_state.py restore --state /путь/к/Dance-analytics-data/state`.
